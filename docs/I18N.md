# Arabic / English localization

Easy Fleet ships in **Arabic (default, RTL)** and **English (LTR)** from a single build.

## Web (`web/src/i18n/`)

| File | Purpose |
| --- | --- |
| `ar.ts` | Arabic dictionary — the source of truth (the original Arabic UI text). |
| `en.ts` | English dictionary, typed as `Messages` so a missing key is a compile error. |
| `index.ts` | `t(key, vars)`, `tDynamic`, `useLocale`, `setLocale`, `applyDocumentLocale`, `intlLocale`. |

- Keys are namespaced: `common.*`, `nav.*`, `enums.<map>.<CODE>`, `labels.*`, and one namespace per page/component (`vehicles.*`, `maintenanceDetail.*`, …). Placeholders use `{name}`.
- Label maps defined at module level (statuses, navigation) use getters (`get label() { return t(...) }`) so they follow the current language.
- `LocaleRoot` (`main.tsx`) re-mounts the app when the language changes; no reload or separate build.
- **Persistence:** `localStorage["ef.locale"]` (survives refresh, logout/login, navigation). Invalid or missing value → Arabic.
- **RTL/LTR:** `<html lang dir>` is set by `applyDocumentLocale`; `public/locale-init.js` sets it before first paint (same-origin script, CSP-safe). Layout uses logical Tailwind utilities (`ms-/me-/start-/end-`); directional icons carry `dir-flip` and are mirrored in LTR.
- **Formatting:** `lib/format.ts` uses `ar-SA` (Latin digits, Gregorian calendar) or `en-GB`. Money is `1,250 ريال` / `SAR 1,250`. Stored values are never changed.
- **Language switcher:** `components/LanguageSwitcher.tsx` — header (compact), login page and public handover/return page (segmented “العربية / English”).
- Every API request sends `X-Locale`; file/report URLs get `?lang=`.

## Server (`server/src/i18n/`)

- `localeMiddleware` reads `X-Locale` or `?lang=` (default `ar`) into an `AsyncLocalStorage`.
- `tr("…Arabic…", ...args)` returns the message in the request language. `catalog.ts` maps the Arabic source text (templates with `{0}`) to English.
- The error handler localizes `HttpError` messages and validation details; zod's built-in technical messages are replaced by friendly messages per issue code.
- **Stored system text** (notifications, system assignment titles, system role names/permission descriptions, automatic quote reasons) stays canonical Arabic in the database and is translated on read by `translateText()`, which only matches known catalog entries/templates.
- **User content is never translated:** names, plates, VINs, IDs, notes, reasons and broadcasts written by users are returned as entered.
- Reports: definitions, JSON column labels and CSV headers follow the language; CSV is UTF-8 with BOM (Arabic opens correctly in Excel); data values are unchanged.

## Adding a string

1. Add the key to `web/src/i18n/ar.ts` and `en.ts` (server: add the Arabic → English pair to `server/src/i18n/catalog.ts` and wrap with `tr()`).
2. `web/src/i18n/i18n.test.ts` and `server/tests/i18n.test.ts` fail on missing keys, mismatched placeholders, Arabic in English, or hardcoded Arabic outside the dictionaries.
